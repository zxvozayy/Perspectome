## Scope

- Ingest and clean the calibration sources in
  [`docs/data-sources.md`](../../docs/data-sources.md) — start with WVS Wave 7
  Turkey; add TÜİK/ISSP/LiTS later if time allows.
- Recode sentinel missing-value codes (e.g. WVS's -1/-2/-4/-5) to null before
  anything else touches the data.
- Verify every variable code against the official WVS codebook before using
  it. A mislabelled item silently poisons everything downstream.
- Build the persona generator: post-stratify/reweight the survey sample to
  TÜİK's published population margins. Use **cross-tabulated** margins
  (age × gender × region × education) where available, not just one-way
  marginals. These post-stratification cells are also the **archetypes**
  Track B queries the LLM with (see
  [rule 33](../../docs/methodology-rules.md)) — expose a `cell_id` per persona.
- Sample attributes from the **empirical** distribution of the survey, not
  from a fitted normal — normals miss skew and inflate correlations between
  derived fields.
- Consistency rules (e.g. age vs. education) **warn, never drop**. Real
  respondents break neat rules; rejecting them biases the population.
- **Held-out discipline is the one rule that can't bend:** conditioning
  fields and attitude fields live in two separate files that are never joined
  back together outside Track C. The field lists live in
  [`src/common/schema.py`](../common/schema.py) — import them, don't retype
  them.
- Raw survey files are never committed (`data/` is git-ignored). Only your
  code and small, clearly-synthetic fixtures go in git.

### The first decision: which WVS items condition, which are held out

Personas built from demographics alone carry very little attitude signal —
demographics explain only a small share of attitude variance, so a
demographics-only persona hits the right marginals while saying almost
nothing about any individual. A values/worldview line in the persona is what
makes personas differ. But every item used to *build* personas can no longer
be used to *validate* them.

So before writing the generator, split the WVS value items into two written
lists — conditioning vs. held-out — and get Hasan (Track C) to sign off.
Put the result in `src/common/schema.py`. This decision is hard to undo.

## What you ship

`data/processed/personas.csv` and `data/processed/heldout.csv` (both
git-ignored, generated by your code — not committed), matching the schema
below, plus the generator code under `src/personas/`.

The persona set is **frozen** once shipped: fixed seed, documented command,
and a `persona_set_hash` (SHA-256 of `personas.csv`) that Track B records on
every run. Regenerating the pool invalidates every earlier measurement, so
it's a PR, not a quiet rerun.

## Rules that bite this track

From [`docs/methodology-rules.md`](../../docs/methodology-rules.md):
2 (personas aren't people), 10 (fit vs. measure split), 26 (one source of
truth for categories), 28 (prove tests can fail), 33 (cells = archetypes).

Also:
- **Leakage test:** put a unique sentinel string into one held-out value in a
  test fixture and assert it never appears in `personas.csv` or anywhere
  Track B's prompts are built from.
- **Lineage test:** regenerate from the raw file with the frozen seed and
  assert you get the identical `persona_set_hash`. Watch for unordered
  queries/dict iteration silently changing order.
- No single global correction coefficient. A correction learned on one topic
  tends to make another topic worse; if you calibrate, do it per item group
  and measure it on held-out data.
- WVS Turkey is from 2018. Note this wherever results are presented — time
  drift is not measured.
