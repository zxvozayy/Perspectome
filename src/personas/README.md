# Track A — Data & Persona Layer

**You own:** turning real survey data into a synthetic, calibrated population —
and nothing downstream of that.

## Scope

- Ingest and clean the calibration sources in
  [`docs/data-sources.md`](../../docs/data-sources.md) — start with WVS Wave 7
  Turkey; add TÜİK/ISSP/LiTS later if time allows.
- Recode sentinel missing-value codes (e.g. WVS's -1/-2/-4/-5) to null before
  anything else touches the data.
- Build the persona generator: post-stratify/reweight the survey sample to
  TÜİK's published population margins (age × gender × region × education).
- **Held-out discipline is the one rule that can't bend:** demographic/
  conditioning fields and attitude fields live in two separate files that are
  never joined back together outside the validation step. If you're not sure
  whether a field is "conditioning" or "held-out," ask before committing it to
  either file — this is the single most important invariant in the whole
  project (see `docs/literature-review.md` on calibration failure modes).
- Raw survey files are never committed (`data/` is git-ignored). Only your
  code and small, clearly-synthetic fixtures go in git.

## What you ship

`data/processed/personas.csv` and `data/processed/heldout.csv` (both
git-ignored, generated by your code — not committed), matching the schema
below, plus the generator code under `src/personas/`.

## The contract (freeze this on day 1)

```
personas.csv — demographic/conditioning fields ONLY
  persona_id        string, unique
  age_band          "18-24" | "25-34" | "35-44" | "45-54" | "55-64" | "65+"
  gender            "male" | "female"
  education_level   "primary" | "secondary" | "vocational" | "bachelor" | "graduate"
  region            Turkish region name
  settlement_type   "urban" | "rural"
  marital_status    "married" | "single" | "divorced" | "widowed"
  employment_status "employed" | "unemployed" | "student" | "retired" | "homemaker"
  income_decile     1-10

heldout.csv — attitude fields, SEPARATE file, same persona_id key
  persona_id            string, matches personas.csv
  political_leaning     1-5 (left to right)
  trust_institutions    1-5
  religiosity           1-5
  economic_optimism     1-5
  risk_tolerance        1-5
```

A 15-row synthetic example of both files is in [`fixtures/`](fixtures/) —
fabricated numbers, not real respondents, just so Tracks B and C have
something to run against from day 1.

Open a PR and say so in the team channel — Tracks B and C are coding against
this schema from day one. A silent breaking change blocks both of them.

## Definition of done

- [ ] WVS Wave 7 Turkey loaded, missing codes recoded to null
- [ ] Post-stratification against at least one TÜİK margin (age × gender, at minimum)
- [ ] `personas.csv` / `heldout.csv` generated, matching the schema above
- [ ] A short written note on calibration error (how far the reweighted sample is from the TÜİK margins)
